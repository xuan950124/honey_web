# LINE 機器人：手機收單、一鍵建物流單

有訂單就推播到你的 LINE，訊息上直接有「**建立物流單**」按鈕。
按下去就建單並把**寄件代碼與驗證碼**回傳到同一個聊天室 ——
包好包裹就能出門，中間不用開電腦。

---

## ⚠ 先做這一件事：把 token 換掉

你剛剛把 **Channel access token 貼在對話裡了**，那串等於官方帳號的密碼 ——
拿到的人可以用你的名義發訊息給所有好友。

**現在就去 LINE Developers → Messaging API → Channel access token → 按「Reissue」。**
舊的會立刻失效，然後把新的填到下面的環境變數。

> 之後貼設定給我看的時候，金鑰那幾行請自己改成 `***`。

---

## 一、要設三個環境變數（Zeabur → 後端服務 → Variables）

```
LINE_CHANNEL_ACCESS_TOKEN=<Messaging API 分頁 → Channel access token>
LINE_CHANNEL_SECRET=<Basic settings 分頁 → Channel secret>
LINE_ADMIN_USER_IDS=          ← 可以留空，改在後台加人
```

前兩個是**憑證**，只能放環境變數 —— 進了資料庫就會被後台表單讀出來顯示，
等於多一個外洩點。收件人名單不是憑證，所以放在後台比較方便。

### 為什麼 Channel secret 不能省

webhook 網址是**公開的**，任何人都能對它發 POST。
LINE 會用這組 secret 對整包資料算一個簽章放在標頭裡，我們驗過才處理。

沒有它的話，別人送一包假的按鈕事件就能叫你的系統去綠界建單 ——
而**超商運費是從你的綠界餘額先扣的**。這是一個花錢的遙控器。

### 收件人可以在後台加，不用改環境變數

**`LINE_ADMIN_USER_IDS` 可以先留空。** 收件人名單改在
**後台 → 網站設定 → LINE 通知機器人 → 誰會收到通知**，
隨時可以加人、移除，不用重新部署。

環境變數那一欄留著當備援 —— 兩邊**取聯集**，都算數。
（在那裡設的 ID 後台移不掉，會標示「來自環境變數」。）

### 加人：用配對碼，不要複製 ID

**可以有很多人**：你、家人、幫忙出貨的人，各自都會收到通知，
也都能按「建立物流單」。

加人的方式：

1. 請那個人**先加官方帳號好友**
2. 後台按「**產生配對碼**」→ 得到六位數字
3. 他在 LINE 聊天室把那六個數字傳過去
4. 完成，機器人會回「設定完成」

配對碼**十分鐘內有效、只能用一次**，而且產生它要先登入後台。

> 為什麼不叫你複製 user ID：那串長得像 `U4af4980629...`，33 個字元。
> 用手機複製再切到電腦貼上，少一個字、多一個空白就整個不會動 ——
> 而且**錯了完全沒有提示**，只會表現成「怎麼都收不到通知」。
> 配對碼把方向反過來，六個數字打錯了它會直接告訴你。
>
> （真的想用 ID 也可以：在聊天室傳「我的ID」。）

> **名單空的 = 沒有任何人能按按鈕。** 空名單當成「誰都不行」，
> 不是「誰都可以」—— 這是刻意的。

## 二、設定 webhook

LINE Developers → 你的 channel → **Messaging API** 分頁：

1. **Webhook URL** 填：
   ```
   https://api.huanglong-honey.com/api/line/webhook
   ```
2. **Use webhook** 打開
3. 按「**Verify**」，要看到成功
4. 順便把 **Auto-reply messages 關掉** —— 不然機器人回一次、
   官方帳號的罐頭訊息再回一次，很吵

---

## 三、確認設定好了

**後台管理 → 網站設定 → LINE 通知機器人**

那一區會列出三個變數各自有沒有填，綠色的「LINE 通知已啟用」才算完成。
Webhook URL 也在那裡，可以直接複製。

按「**傳一則測試訊息**」是最快的驗證方式 —— 收到訊息就是通了，
沒收到就看它回的錯誤，不用逐項猜是哪一段斷掉。

> **不要直接在瀏覽器打開 `/api/line/status`。** 那支端點只有工作人員能看，
> 而在網址列打開是一次普通的瀏覽器導航，**不會帶登入權杖**（權杖存在
> localStorage，只有網頁用 fetch 呼叫時才會加上去），所以一定看到
> 「登入憑證無效或已過期」。要看狀態就在後台頁面裡看。
>
> 這一區**不會顯示任何金鑰內容**，只說「有沒有填」。

## 四、實際怎麼運作

### 收到訂單

- **線上付款**：綠界通知付款成功時才推播 —— 那時候錢才是真的進來了
- **貨到付款**：訂單一成立就推播（沒有線上付款那一步）

推播的卡片上有：金額、訂單編號、收件人、商品、取貨門市、付款狀態，
以及兩顆按鈕：**建立物流單**、**打開後台**。

### 按下「建立物流單」

1. 系統驗簽章 → 確認是 LINE 傳來的
2. 比對你的 user ID → 確認是你按的
3. 呼叫綠界建單（跟後台按那顆按鈕是**同一份程式碼**）
4. 回傳一張卡片，寄件代碼用超大字顯示

> 寄件代碼字級刻意放到最大 —— 那是要站在超商機台前照著打的東西。

**同一筆按兩次不會建兩次單**，第二次會直接把既有的寄件代碼再顯示一次。
重複建單等於多付一次運費。

### 建單失敗

會回一段看得懂的說明（餘額不足、寄件人資料沒填…）與最關鍵的第一步。
完整處理步驟還是在後台看，手機塞不下那麼多字。

## 五、可以在聊天室打的指令

| 指令 | 作用 |
|---|---|
| `訂單` | 列出待建物流單的訂單（最多 4 張卡片）|
| `我的ID` | 查自己的 LINE 使用者 ID |

「我的ID」對任何人開放，其他指令只有白名單裡的人能用。
陌生人傳訊息會收到一句客氣的招呼，不會看到任何訂單資料。

## 六、安全性摘要

| 關卡 | 擋掉什麼 |
|---|---|
| **簽章驗證** | 別人偽造 LINE 的請求打進來 |
| **白名單** | 加你好友的陌生人按按鈕花你的錢 |
| **重複建單保護** | 手滑按兩次多付一次運費 |
| **不回傳金鑰** | 狀態端點被看到也不會外洩設定 |

簽章比對用的是 `compare_digest` 而不是 `==` ——
一般的字串比較會在第一個不同的位元組就回傳，
攻擊者可以從回應時間反推出正確的簽章。

> **通知失敗永遠不會影響下單。** LINE 掛掉、token 過期、網路不通，
> 都只會在伺服器日誌留一行警告，客人照常結帳。

## 七、常見狀況

**Q：webhook Verify 一直失敗**
先確認後端活著：打開 `https://api.huanglong-honey.com/api/health`。
再確認 `LINE_CHANNEL_SECRET` 填的是 **Basic settings** 那一頁的，
不是 Messaging API 那頁的 token。

**Q：收不到訂單通知**
後台那一區是不是綠色的「LINE 通知已啟用」？
「誰會收到通知」如果是空的，系統不知道要推給誰 —— 用配對碼加自己進去。

**Q：按了按鈕沒反應**
你在不在「誰會收到通知」的名單裡？不在的話用配對碼加進去。

**Q：配對碼傳過去沒反應**
確認 webhook 有設好而且 Verify 過（沒有 webhook 的話機器人收不到你的訊息）。
另外配對碼只有十分鐘，過了就重新產生一組。

**Q：想改成推到群組**
群組要用 group ID 而不是 user ID，而且機器人要先被加進群組。
目前的白名單比對的是**個人 ID**，要用群組的話跟我說，要改一段程式。
