# 會員帳號、Email 驗證與寄信設定

本文說明四項功能：**顯示密碼、忘記密碼、Email 驗證、管理員手機版預覽**。

---

## 一、顯示密碼勾選框

註冊、登入、重設密碼、變更密碼的所有密碼欄位下方，都有「顯示密碼」的勾選框。

勾起來就能看到自己打了什麼，比要求輸入兩次更不容易出錯。
確認密碼欄刻意**不放**這個勾選框 —— 讓它保持遮蔽才有再確認一次的意義。

---

## 二、忘記密碼

### 買家怎麼用

1. 登入頁 → 點「忘記密碼？」
2. 輸入註冊的 Email → 送出
3. 收信 → 點信中的按鈕 → 設定新密碼 → 自動導回登入頁

### 安全性設計

| 機制 | 說明 |
|---|---|
| **不透露帳號是否存在** | 不管這個 Email 有沒有註冊過，畫面都回同一句話。避免被拿來探測哪些信箱是會員 |
| **連結只能用一次** | 用過就失效，重按信中連結會提示重新申請 |
| **1 小時後過期** | 過期會明確告訴使用者，並附上重新申請的按鈕 |
| **申請新的會讓舊的失效** | 連續申請兩次，只有最新那封的連結有效 |
| **資料庫不存原始連結** | 只存 SHA-256 雜湊，資料庫外洩也無法反推出可用連結 |
| **60 秒冷卻** | 同一帳號短時間內重複申請不會一直寄信 |
| **重設後自動完成信箱驗證** | 收得到信就代表信箱是本人的 |

## 三、Email 驗證

### 流程

1. 註冊完成 → 系統自動寄出驗證信，畫面提示「請到信箱查看」
2. 會員中心上方會有紅色提醒橫幅，附「重寄驗證信」按鈕
3. 點信中連結 → 驗證完成，橫幅自動消失

驗證連結 **24 小時**有效，同樣是一次性、只存雜湊。

### 要不要強制驗證才能下單

預設**不強制**（買家沒驗證也能買，降低結帳流失）。
想改成強制的話，`backend/.env` 設定：

```ini
REQUIRE_EMAIL_VERIFIED=true
```

## 四、寄信設定（SMTP）

### 沒設定也能開發

`SMTP_HOST` 留空時，信件不會真的寄出，而是**存成 HTML 檔放在 `backend/outbox/`**，
用瀏覽器打開就能看到完整的信件內容和連結。等於一個本機假信箱。

而且開發模式下，畫面會直接顯示驗證／重設連結，可以完全不用收信就測完整個流程：

- 註冊完成頁 → 「直接完成驗證」按鈕
- 忘記密碼送出後 → 「直接前往重設密碼」按鈕
- 會員中心重寄驗證信 → 連結顯示在提示訊息裡

> 這些連結**只會**在 `APP_ENV=development` 且沒設定 SMTP 時出現。
> 設成 `production` 之後永遠不會回傳，不用擔心外洩。

### 用 Gmail 寄信

Gmail 不接受一般登入密碼，要用「應用程式密碼」：

1. 到 [Google 帳號安全性](https://myaccount.google.com/security) 開啟**兩步驟驗證**
2. 搜尋「應用程式密碼」，產生一組 16 碼的密碼
3. 填進 `backend/.env`：

```ini
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=你的帳號@gmail.com
SMTP_PASSWORD=十六碼應用程式密碼
SMTP_FROM=你的帳號@gmail.com
SMTP_FROM_NAME=皇龍蜂蜜
SMTP_TLS=true
SMTP_SSL=false
```

4. **重啟後端**（改 `.env` 不會自動重載）

> Gmail 免費帳號每天約有 500 封的寄送上限。
> 訂單量大之後建議改用 SendGrid、Brevo、Amazon SES 這類寄信服務，
> 設定方式一樣，只是換掉 SMTP 主機與帳密。

### 其他常見服務

| 服務 | SMTP_HOST | 埠 | 備註 |
|---|---|---|---|
| Gmail | `smtp.gmail.com` | 587 | 需應用程式密碼 |
| Outlook | `smtp-mail.outlook.com` | 587 | |
| SendGrid | `smtp.sendgrid.net` | 587 | 使用者固定填 `apikey` |
| Brevo | `smtp-relay.brevo.com` | 587 | |

用 465 埠的服務請設 `SMTP_SSL=true`、`SMTP_TLS=false`。

## 五、信件被丟到垃圾郵件怎麼辦

這幾乎一定會發生在開發階段，原因有三個。

### 原因一：信裡的連結指向 `localhost`（最主要）

一封信叫收件人「點這裡驗證」，但連結指到 `http://localhost:5173` 這種
公開網路上根本不存在的位址 —— 這是最典型的釣魚信特徵，Gmail 幾乎必定歸類為垃圾郵件。

**這個沒辦法靠調整信件內容解決，只能等你有真正的網域。**
接上 Cloudflare Tunnel、把 `FRONTEND_BASE_URL` 換成 `https://shop.你的網域.com` 之後，
這一項就消失了，命中率會大幅改善。

### 原因二：郵件標頭不完整（已修正）

正常的郵件軟體都會加上 `Date`、`Message-ID` 等標頭，缺了就會被當成程式亂發的信。
現在已補齊：

| 標頭 | 作用 |
|---|---|
| `Date` | 寄送時間，缺少是明顯的機器發信特徵 |
| `Message-ID` | 郵件唯一識別碼，網域與寄件者一致才不會被視為偽造 |
| `Reply-To` | 可回覆的地址 |
| `Auto-Submitted: auto-generated` | 標記為系統交易通知，不是行銷信 |

同時信件也改成**純文字 + HTML 雙格式**。只有 HTML 沒有純文字版本也是扣分項，
而且純文字版是過濾器主要分析的內容。

### 原因三：用個人 Gmail 帳號寄「品牌信」

寄件者顯示「皇龍蜂蜜」但實際地址是個人 Gmail，這種不一致會被輕微扣分。
加上這是一個全新的寄信模式，Gmail 對沒有信譽紀錄的寄件行為本來就比較保守。

---

### 現在可以做的

**1. 手動標記為「不是垃圾郵件」**

收到後把信移到收件匣，並把寄件地址加入聯絡人。
Gmail 的過濾是**針對每個收件者學習**的，標記幾次之後你自己的信箱就不會再誤判。
測試階段這樣就夠用了。

**2. 提醒買家檢查垃圾郵件匣**

註冊完成頁與忘記密碼頁都已經有這句提示。

### 真的要營業時該怎麼做

用個人 Gmail 寄交易信，長期一定會有到達率問題。正式營運建議改用
**專門的交易郵件服務**，搭配自己的網域：

| 服務 | 免費額度 | 特點 |
|---|---|---|
| **Resend** | 每月 3,000 封 | 設定最單純，開發者友善 |
| **Brevo**（原 Sendinblue）| 每天 300 封 | 介面中文化程度高 |
| **SendGrid** | 每天 100 封 | 老牌，文件完整 |
| **Amazon SES** | 極便宜（約 US$0.1／千封）| 設定較繁瑣 |

這些服務會請你在網域的 DNS 加上三筆記錄：

- **SPF** — 宣告「這些伺服器可以用我的網域寄信」
- **DKIM** — 用金鑰對信件簽章，證明沒被竄改
- **DMARC** — 告訴收件方「驗證失敗的信該怎麼處理」

設定好這三項之後，信件才會被穩定投遞到收件匣。
本專案只要把 `.env` 的 SMTP 主機與帳密換成該服務提供的值就行，程式不用改。

> 順序建議：先用 Gmail 把功能測通 → 買網域接 Cloudflare Tunnel（連結問題消失）
> → 要開始賣的時候再換成 Resend 之類的服務並設定 SPF/DKIM。

## 六、管理員手機版預覽

用**工作人員帳號**登入後，畫面右下角會出現「**手機版預覽**」按鈕（一般會員看不到）。

點開後可以：

- 切換 **iPhone 15 / iPhone SE / Android / iPad** 四種尺寸
- **直向／橫向**切換
- 在預覽畫面裡**直接點擊操作**，跟真的用手機一樣
- 按 **Esc** 或「關閉」離開

### 為什麼看到的是真實畫面

預覽用的是 iframe，不是單純把容器縮窄。
因為 CSS 的 media query 判斷的是「可視區域寬度」而不是容器寬度，
只有 iframe 才會讓網站真的以手機寬度重新計算版面 —— 導覽列收成漢堡選單、
商品從四欄變一欄、表格橫向捲動，全部都是使用者手機上會看到的樣子。

預覽會從**你目前所在的頁面**開始，所以可以邊改內容邊確認手機上的呈現。

## 七、新增的 API

| 方法 | 路徑 | 說明 |
|---|---|---|
| POST | `/api/auth/verify-email/resend` | 重寄驗證信（需登入，有 60 秒冷卻）|
| POST | `/api/auth/verify-email/confirm` | 用連結中的權杖完成驗證 |
| POST | `/api/auth/password/forgot` | 申請重設密碼 |
| POST | `/api/auth/password/reset` | 用連結中的權杖設定新密碼 |
| POST | `/api/auth/password/change` | 已登入時變更密碼（需驗證舊密碼）|

新增前台頁面：`/forgot-password`、`/reset-password`、`/verify-email`

## 八、資料表變動

程式啟動時會自動補上缺少的欄位，**不需要重建資料庫**。

`users` 新增：

| 欄位 | 說明 |
|---|---|
| `email_verified` | 是否已完成信箱驗證 |
| `email_verified_at` | 驗證完成時間 |

新增資料表 `auth_tokens`：驗證信與重設密碼的一次性權杖（只存雜湊）。

### 順帶修正的時區問題

原本時間欄位用的是資料庫的時鐘（`NOW()`），而程式比對時用的是 Python 的本地時間。
如果資料庫伺服器設在 UTC，兩者會差 8 小時，會造成：

- 寄信冷卻判斷永遠不成立
- 送給綠界的交易時間 `MerchantTradeDate` 差 8 小時

現在全部改用程式端的時鐘，資料庫與程式使用同一個時間來源。
既有資料不受影響。

## 九、常見問題

**Q：註冊後沒收到驗證信**
先確認 `.env` 的 SMTP 有沒有設定。沒設定的話信件在 `backend/outbox/`，
或直接用畫面上顯示的連結。有設定卻收不到，請檢查垃圾郵件匣。

**Q：出現「剛剛才寄出過，請等 60 秒後再試」**
這是防濫用的冷卻機制。想調整就改 `.env` 的 `EMAIL_RESEND_COOLDOWN`（單位：秒），改 0 是關閉。

**Q：改了 `.env` 卻沒生效**
`--reload` 只監看 `.py` 檔。改 `.env` 要手動重啟後端。

**Q：右下角沒看到「手機版預覽」按鈕**
那個按鈕只有工作人員帳號看得到。請確認登入的是 `role = staff` 的帳號。

**Q：正式上線前要注意什麼**
把 `.env` 的 `APP_ENV` 改成 `production`，並確實設定 SMTP。
`production` 模式下 API 不會再回傳任何驗證連結。
