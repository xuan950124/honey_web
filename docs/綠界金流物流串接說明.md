# 綠界 ECPay 金流／物流串接說明

本站已完成綠界串接，支援：

| 類別 | 支援項目 |
|---|---|
| **付款** | 信用卡、ATM 虛擬帳號、超商代碼繳費、貨到付款（代收貨款） |
| **超商取貨** | 7-ELEVEN 交貨便（C2C）、全家店到店（C2C） |
| **宅配** | 黑貓宅急便（常溫／冷藏／冷凍）、中華郵政（僅常溫） |

**目前預設是綠界「測試環境」**，用綠界公開的測試金鑰，不會真的扣款也不會真的出貨。

---

## 一、先搞懂一件事：回呼網址必須「對外連得到」

綠界有兩種通知方式，差別很重要：

| 類型 | 誰發出請求 | localhost 可以嗎 |
|---|---|---|
| 電子地圖選門市 | **買家的瀏覽器** | ✅ 可以，本機就能測 |
| 付款結果通知 `ReturnURL` | **綠界的伺服器** | ❌ 不行，需要公開網址 |
| 物流狀態通知 `ServerReplyURL` | **綠界的伺服器** | ❌ 不行，需要公開網址 |

也就是說：**本機開發時，選門市、下單、跳轉付款頁、建立物流單拿寄件代碼，全部都能正常測試。**
唯一收不到的是「付款完成」和「物流狀態變更」的自動通知。

### 本機要測付款通知的話

用 ngrok 之類的工具開一個公開網址：

```bash
ngrok http 8000
```

拿到網址後填進 `backend/.env`：

```ini
BACKEND_BASE_URL=https://xxxx-xx-xx.ngrok-free.app
```

重啟後端即可。**綠界只接受 80 / 443 埠**，所以不能直接填 `http://你的IP:8000`。

### 不想架 ngrok 的替代方案

後台訂單展開後有「**向綠界查詢付款狀態**」按鈕，會主動打綠界的查詢 API 把付款狀態補回來。
本機開發時用這個就夠了。

## 二、買家的完整流程

### 超商取貨（C2C 店到店）

1. 買家在購物車選「7-ELEVEN 超商取貨」→ 按「選擇取貨門市」
2. 開新視窗跳出綠界電子地圖（測試環境會直接回傳一間固定的測試門市）
3. 選好門市 → 視窗自動關閉，門市資料回填到結帳頁
4. 選付款方式 → 送出訂單
5. 信用卡／ATM／超商代碼 → 導向綠界付款頁；貨到付款 → 直接完成
6. 付款完成後導回訂單頁 `/order/訂單編號`

### 宅配

1. 選「黑貓宅急便」→ 出現溫層選項（常溫／冷藏／冷凍）
2. 填收件地址與郵遞區號
3. 之後流程與上面相同

> 中華郵政不支援冷藏冷凍，也不支援貨到付款，系統會自動擋下不合法的組合。

## 三、你（賣家）的出貨流程

進入 **後台管理 → 訂單與出貨管理**，可用「待出貨」篩選出已付款待處理的訂單。

1. 展開訂單 → 按「**建立物流單並取得寄件代碼**」
2. 系統向綠界建單，回傳：
   - **超商**：寄件代碼 `CVSPaymentNo`（7-11 另有驗證碼 `CVSValidationNo`）
   - **宅配**：託運單號 `BookingNote`
3. 出貨方式：
   - **7-ELEVEN**：包裹拿到門市，在 **ibon** 輸入寄件代碼 → 印出單據 → 貼上 → 交給店員
   - **全家**：在 **FamiPort** 操作，或按「列印託運單」自己印
   - **宅配**：按「列印託運單」印出，或通知宅配員到府收件
4. 寄件時**不用先付運費**，物流費由綠界從你的帳戶餘額扣款

> ⚠️ 綠界帳戶餘額不足會導致無法建立物流單，記得在廠商後台預存一筆金額。

## 四、切換到正式環境

### 1. 先向綠界申請

到 [綠界官網](https://www.ecpay.com.tw/) 註冊廠商帳號，分別申請：

- **全方位金流**（信用卡等付款方式）
- **物流**，申請時要選 **C2C** 或 B2C
  - **C2C（店到店）**：適合初期單量少，不用測標，直接就能寄
  - **B2C（大宗寄件）**：需先完成「測標」作業，測標沒過就寄件會被退回且運費自付

> 注意：綠界規定，申請 C2C 的廠商只能串 C2C 的電子地圖與物流子類型，不能混用。
> 本站目前實作的是 **C2C**。

### 2. 取得金鑰

登入[綠界正式後台](https://vendor.ecpay.com.tw/) → 系統設定 → 系統介接設定 → 介接資訊，
取得 `MerchantID`、`HashKey`、`HashIV`。

金流與物流是分開的兩組，請分別取得。

### 3. 修改 `backend/.env`

```ini
# 切成正式環境
ECPAY_ENV=production

# 金流（全方位金流）
ECPAY_MERCHANT_ID=你的金流廠商編號
ECPAY_HASH_KEY=你的金流HashKey
ECPAY_HASH_IV=你的金流HashIV

# 物流 C2C 店到店
ECPAY_C2C_MERCHANT_ID=你的物流廠商編號
ECPAY_C2C_HASH_KEY=你的物流HashKey
ECPAY_C2C_HASH_IV=你的物流HashIV

# 物流 宅配（正式環境通常和上面 C2C 是同一組，填一樣即可）
ECPAY_HOME_MERCHANT_ID=你的物流廠商編號
ECPAY_HOME_HASH_KEY=你的物流HashKey
ECPAY_HOME_HASH_IV=你的物流HashIV

# 換成你的正式網域（一定要 https，且是 443 埠）
BACKEND_BASE_URL=https://api.你的網域.com
FRONTEND_BASE_URL=https://你的網域.com
```

### 4. 後台補齊寄件人資訊

**後台管理 → 網站設定 → 寄件人資訊**，這些是建立物流單必要的：

| 欄位 | 說明 |
|---|---|
| 寄件人姓名 | 綠界規定 **2~5 個中文字**，不可含數字或符號。C2C 退件要憑證件領取，**別填公司名稱** |
| 寄件人手機 | 09 開頭 10 碼，退貨通知簡訊會寄到這 |
| 寄件人郵遞區號 | **宅配必填** |
| 寄件人地址 | **宅配必填**，需完整且超過 6 個字 |

同一頁還可以設定運費、滿額免運門檻、貨到付款手續費。

## 七、安全性

- **卡號永遠不會經過你的主機**。我們只把訂單資訊 POST 到綠界的付款頁，
  買家在綠界的網域輸入卡號。這是 PCI DSS 建議的做法，你不需要處理卡片資料合規問題。
- 所有綠界回呼都會驗證 **CheckMacValue**（物流用 MD5、金流用 SHA256），
  偽造的通知會被擋下並回 `0|CheckMacValue Error`。
- 付款通知額外比對金額，`TradeAmt` 與訂單金額不符會拒絕，防止竄改。
- 所有回呼往來都記錄在 `ecpay_logs` 資料表，出問題可回溯查證。

> 檢查碼實作已用綠界官方文件公布的兩組測試向量驗證過，計算結果完全一致。

## 八、資料表新增的欄位

程式啟動時會自動比對並補上缺少的欄位（`sync_schema()`），**不會刪除或改動既有資料**，
所以升級不需要重建資料庫。

`orders` 資料表新增：

| 欄位 | 說明 |
|---|---|
| `subtotal` / `shipping_fee` | 商品小計與運費（`total_amount` 為應付總額）|
| `shipping_method` | 送貨方式 |
| `cvs_store_id` / `cvs_store_name` / `cvs_address` / `cvs_telephone` | 買家選的門市 |
| `receiver_zipcode` / `temperature` / `specification` / `distance` | 宅配相關 |
| `payment_method` / `payment_status` / `is_collection` | 付款方式與狀態 |
| `ecpay_trade_no` / `payment_type` / `paid_at` | 綠界交易資訊 |
| `payment_no` / `payment_bank_code` / `payment_expire_date` | ATM 虛擬帳號、超商繳費代碼 |
| `logistics_status` / `allpay_logistics_id` | 物流狀態 |
| `cvs_payment_no` / `cvs_validation_no` / `booking_note` | **寄件代碼**、驗證碼、託運單號 |

新增資料表 `ecpay_logs`：綠界回呼與 API 往來記錄。

## 十、常見問題

**Q：點「選擇取貨門市」沒反應**
瀏覽器擋掉彈出視窗了，請允許本站開啟新視窗。綠界規定電子地圖不能放 iframe，所以一定要開新視窗。

**Q：測試環境選門市沒有跳出地圖**
正常。綠界測試環境是固定回傳一間測試門市，不會真的顯示地圖。

**Q：建立物流單失敗，說「姓名格式錯誤」**
綠界的姓名檢核很嚴：2~5 個中文字，不可含數字或特殊符號。
系統已會自動清洗，但如果買家填的名字清洗後仍不合規，請手動修正。

**Q：建立物流單失敗，說帳戶餘額不足**
到綠界廠商後台預存一筆金額，物流費會從餘額扣。

**Q：付款完成了但訂單還是顯示未付款**
`ReturnURL` 沒收到通知。本機開發是正常現象，按後台的「向綠界查詢付款狀態」即可補回。
正式環境請確認 `BACKEND_BASE_URL` 是公開網址、走 443 埠、且防火牆沒擋綠界。

**Q：可以改成 B2C 大宗寄件嗎**
可以，把 `models.py` 的 `SHIPPING_MAP` 子類型從 `UNIMARTC2C` / `FAMIC2C`
換成 `UNIMART` / `FAMI`，但 B2C 需先完成綠界的「測標」作業。
