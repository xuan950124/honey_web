# 綠界審核期間怎麼開賣

你目前的狀態（2026/08/18）：

| 服務 | 狀態 |
|---|---|
| 物流 | **已開通** |
| 金流－信用卡收款 | 審核中（3~5 個工作日）|
| 金流－非信用卡收款 | 審核中（3~5 個工作日）|

**結論：物流已經可以用了，所以你現在就能開賣 —— 先只開放「貨到付款」。**

---

## 一、為什麼貨到付款不用等金流

貨到付款走的是**物流的「代收貨款」**，不是金流服務：

```
客人到超商取貨 → 付現給店員 → 綠界代收 → 撥到你的綠界帳戶
```

整條路上沒有經過金流服務，所以物流一開通就能用。

綠界後台那句「提領款項須開通金流服務」的意思是：
**錢會進到你的綠界帳戶，但要等金流審核通過才提領得出來。**
錢跑不掉，只是先放在那裡。反正金流也只剩 3~5 個工作日。

---

## 二、怎麼設定

後端加兩個環境變數（Zeabur 的後端服務 → Variables）：

```
ECPAY_LOGISTICS_ENV=production

ECPAY_C2C_MERCHANT_ID=<你的正式 C2C 廠商編號>
ECPAY_C2C_HASH_KEY=<正式 HashKey>
ECPAY_C2C_HASH_IV=<正式 HashIV>

ECPAY_HOME_MERCHANT_ID=<你的正式宅配廠商編號>
ECPAY_HOME_HASH_KEY=<正式 HashKey>
ECPAY_HOME_HASH_IV=<正式 HashIV>
```

**`ECPAY_ENV` 保持 `stage` 不要動** —— 金流還沒過。

重新部署後，系統會自動：

- 結帳頁**只顯示「貨到付款」**，信用卡／ATM／超商代碼會變成灰色，
  並標明「線上付款服務審核中，目前僅開放貨到付款」
- 直接打 API 想繞過也會被擋（回 400，不是只擋畫面）
- 測試卡號的提示消失（那是開發中才需要的）
- 後台總覽顯示「金流：測試．物流：正式」與現在能做什麼

### 金流過了之後

```
ECPAY_ENV=production
ECPAY_MERCHANT_ID=<正式商店代號>
ECPAY_HASH_KEY=<正式 HashKey>
ECPAY_HASH_IV=<正式 HashIV>
```

信用卡與 ATM 會自動一起開放，不用再改程式。

---

## 三、為什麼要擋線上付款

這是這次改動裡最重要的一件事。

如果「物流正式 + 金流測試」時還讓客人選信用卡，會發生：

1. 客人被帶到綠界的**測試**付款頁
2. 他刷了，畫面顯示成功
3. 訂單成立，你照著出貨
4. **但你一毛錢都沒收到**

客人以為買到了、你以為收到了，錢卻不存在。這種錯誤比「不能結帳」嚴重得多，
所以系統在前端與後端都擋住 —— **只擋畫面是不夠的**，直接打 API 一樣要擋。

> 兩邊都還在測試時不擋。那是開發中的正常狀態，你需要能測所有付款方式。

---

## 四、只賣貨到付款要注意什麼

| 事項 | 說明 |
|---|---|
| 金額上限 | 超商代收單筆 20,000 元 |
| 手續費 | 代收金額 × 0.75%（每筆最低 3 元），週二結算時扣 |
| 棄件風險 | 客人不取貨的話，來回運費由你負擔 |
| 撥款 | 一般賣家週二撥款到綠界帳戶，提領要等金流開通 |

**棄件是貨到付款最大的風險。** 建議：

- 訂單成立後用 LINE 主動確認一次
- 首購客人的金額先設個上限（例如 2,000 元）
- 後台的「訂單管理」可以看到誰沒取貨，多次未取的帳號可以停用貨到付款

## 五、順便：地圖導航被導到隔壁的問題

你發現「規劃路線」導到 89 號而不是 89-6 號 —— 那是同一個根因：

**Google 的資料庫裡沒有「89-6號」這個點，它會就近對到「89號」。**

原本只有地圖的紅點用座標（如果你有填），導航連結還是送地址過去讓 Google 重新猜一次。
現在改成**兩個都用座標**。

### 你要做的

到 **後台 → 網站設定 → Google 地圖位置（座標）** 填座標：

1. 打開 Google 地圖，找到你家門口
2. 對著那個位置按**滑鼠右鍵**
3. 點最上面那組數字（例如 `25.098406, 121.665791`）—— 會自動複製
4. 貼到那個欄位，儲存

填完之後：

- 地圖的紅點插在你家門口
- **「規劃路線」導到同一個點**
- 頁面上「位置可能與實際門牌略有落差」那句提醒會自動消失（因為不再有落差）

沒填的話，工作人員登入時會在地圖下方看到提醒（客人看不到）。

> 從你貼的網址看，Google 把 89-6 號解析成 `25.0956825, 121.6668334` ——
> 那是它猜的 89 號位置。請用右鍵取你**實際門口**的座標，不要用這一組。

## 六、測試

```
cd backend  && python tests/test_ecpay_env.py             (61 項)
cd frontend && node tests/cart-stock-and-map.test.mjs     (75 項)
```

重點涵蓋：

- 物流可以單獨切正式，金流留在測試
- 那種狀態下線上付款**在後端也被擋住**（不是只擋畫面）
- 兩邊都測試、兩邊都正式時都不會誤擋
- 有座標時導航與地圖用**同一組座標**；沒座標時才退回用地址
- `production` / `Production` / `prod` / `正式` 都認得，`true` / `1` 不算
