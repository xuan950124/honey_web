> **先講清楚：這份不是法律意見。** 內容參考食品安全衛生管理法、個人資料保護法、
> 消費者保護法與「通訊交易解除權合理例外情事適用準則」整理，
> 但實際要求請以食藥署、經濟部與消保單位的公告為準。
> 正式營業前建議請律師或會計師看過一次，費用不高但能省掉很多麻煩。

# 上線前必辦清單

分成「非做不可」與「做了會更好」。打勾的順序就是建議的處理順序。

---

## 一、非做不可（沒做會有法律或金錢風險）

### ☐ 1. 綠界切到正式環境

**沒做的後果：客人的錢收不到。**

後端環境變數：

```
ECPAY_ENV=production
ECPAY_MERCHANT_ID=<綠界給你的正式商店代號>
ECPAY_HASH_KEY=<正式 HashKey>
ECPAY_HASH_IV=<正式 HashIV>
```

物流的金鑰是另一組（C2C 與宅配各一組），一併換掉。

沒改的話後台總覽會一直跳紅色警告，結帳頁也會顯示測試卡號提示 —— 這是刻意的。

### ☐ 2. 填齊業者資訊

**後台 → 政策條款 → 業者資訊**

| 欄位 | 需要嗎 | 說明 |
|---|---|---|
| 商號／蜂場名稱 | **必填** | 例：皇龍養蜂場。食安法第 22 條要求的標示項目 |
| 負責人 | 建議填 | 例：黃皇龍 |
| 廠商地址 | 建議填 | 食品標示上的地址，留空會用聯絡地址 |
| 廠商電話 | 建議填 | 留空會用訂購專線 |
| 統一編號 | **不用** | 見下方「你不需要辦的事」 |
| 食品業者登錄字號 | **不用**（可自願辦） | 同上 |

沒填的欄位前台不會顯示空白列。

### ☐ 3. 補齊每個商品的食品標示

**後台 → 商品管理 → 編輯 → 食品標示**

網路販售包裝食品，這些在**購買前**就要揭露：

| 項目 | 填在哪 |
|---|---|
| 品名 | 商品名稱 |
| 內容物名稱 | 商品的食品標示（留空用共用預設「100% 蜂蜜」）|
| 淨重／內容量 | 商品的食品標示（留空會用「規格」）|
| 原產地（國）| 商品的「產地」欄位 |
| 有效日期／保存期限 | 商品的食品標示 |
| 保存方式 | 留空用共用預設 |
| 食品添加物名稱 | 純蜜沒有就留空 |
| 過敏原資訊 | 留空用共用預設 |
| 營養標示 | 商品的食品標示 |
| 廠商名稱地址電話 | 政策條款 → 業者資訊（全站共用）|

用工作人員帳號打開商品頁，缺哪幾項會直接列出來（客人看不到那段提示）。

> **關於「純蜂蜜」的標示**：2023 年 7 月 1 日起，
> 只有未添加其他成分的產品才能標示為「蜂蜜」「純蜂蜜」「100% 蜂蜜」。
> 你的是純的就沒問題，但**內容物欄位明確寫出「100% 蜂蜜」對自己是保護**——
> 系統的共用預設已經幫你填好這一句。

### ☐ 4. 檢查三份政策的內容

已經幫你寫好草稿，在 **後台 → 政策條款 → 政策內文**，前台網址是
`/privacy`、`/terms`、`/refund`，頁尾也有連結。

**退換貨那份要特別看。** 食品可以依「通訊交易解除權合理例外情事適用準則」
排除七天猶豫期，但**必須在消費者下單前明確告知**，沒告知就不能排除。
所以系統在購物車的「送出訂單」按鈕正上方就會顯示重點摘要 ——
**那一段不要刪掉**，它是排除猶豫期的法律依據。

服務條款裡的管轄法院預設寫「臺灣基隆地方法院」，如果你的營業登記地不同，記得改。

### ☐ 5. 換掉預設密碼與金鑰

- `.env` 的 `SECRET_KEY` 換成一段長的隨機字串（換了之後所有人要重新登入）
- 管理員密碼不要用手機號碼或 `admin1234`
- `CORS_ORIGINS` 只留正式網域

### ☐ 6. 商品照片

目前多個商品沒有主圖。後台總覽會列出來，點一下就去編輯。

**沒有照片的商品幾乎不會有人下單**，這比任何文案調整都重要。

## 二、你不需要辦的事（很多人卡在這裡）

這一節是為了讓你**不要去辦不需要辦的東西**。以下三件事常被當成「賣食品的必要條件」，
但以你目前「自產自銷的養蜂場」的身分，都不適用。

### ✗ 統一編號、營業登記

農民銷售自己收穫的農、林、漁、牧產物、副產物，以及自己生產的農產品（含自產農產加工品），
依**加值型及非加值型營業稅法第 8 條第 1 項第 19 款、第 29 條**免辦營業登記、免徵營業稅。
**開農民收據即可，不需要統編，也不用開統一發票。**

### ✗ 食品業者登錄（非登不可）

強制登錄的對象是**具有商業登記、公司登記、工廠登記的販售業者，
以及具有稅籍登記或經核准的攤販**。你都沒有，就不在強制範圍內。

> 不過**自願登錄**可以考慮。字號印在瓶身與網站上，對第一次買的人是很直接的信任感，
> 而且免費、線上就能辦（`fadenbook.fda.gov.tw`）。辦了就填到後台，
> 頁尾與每個商品的食品標示會自動顯示。

### ✗ 綠界電子發票

綠界的電子發票服務**僅限有統編的公司戶申請**，個人賣家帳號拿不到。
不用去找那個功能在哪裡 —— 本站的結帳流程本來就沒有開發票欄位，
綠界串接也沒有帶任何發票參數。

---

## ⚠ 但有一條界線要顧住

上面三項的前提都是「**自產自銷**」。

哪天你開始**收購別的蜂農的蜜再轉賣**，那一部分就跟一般商家沒兩樣，
**要辦稅籍登記、要開統一發票**，食品業者登錄也會變成強制。

首頁寫的「自家蜂場直送、不經過中盤」正好就是自產的佐證，這個定位要維持住。

### 這幾件事不會因為你是農民就免除

| 項目 | 依據 | 網站的處理 |
|---|---|---|
| 包裝食品標示 | 食安法第 22 條、包裝蜂蜜及其糖漿類產品標示規定 | 商品頁的食品標示區，缺項會提示 |
| 食品良好衛生規範準則（GHP） | 只要有製造加工行為就適用 | 網站管不到，是作業現場的事 |
| 退換貨與鑑賞期告知 | 消費者保護法 | `/refund` 與結帳前的告知區塊 |
| 隱私權政策 | 個人資料保護法（你收會員與收件人資料）| `/privacy` |
| 賣家聯絡資訊 | 消保法 | 頁尾與 `/contact` |

> 標「純蜂蜜」就必須是 100% 純蜜，這跟稅籍完全無關。

**稅務細節建議打國稅局免付費專線 0800-000-321 問一次**（他們對自產自銷這題很熟），
標示的部分問**基隆市衛生局食品科**最快。

## 三、做了會更好

### ☐ 7. Google Search Console

1. 到 `search.google.com/search-console` 新增資源
2. **兩個網域都要驗證**：`huanglong-honey.com` 和 `api.huanglong-honey.com`
   （用 DNS TXT 驗證，兩筆都加在同一個 DNS 設定裡）
3. 提交 sitemap：`https://api.huanglong-honey.com/sitemap.xml`

> 為什麼要驗證兩個：sitemap 放在 API 網域，但裡面列的是主網域的網址，
> 這在 Google 叫「跨網域提交」，兩邊都驗證過才會生效。
> 兩個網域都是你的，加一筆 DNS 記錄的事。

sitemap 是後端**依實際商品自動產生**的，新增商品不用重做，
但已下架的商品會自動排除（讓 Google 收錄會 404 的頁面反而扣分）。

### ☐ 8. 分享預覽的封面圖

LINE 和 Facebook 的預覽卡片**不會執行 JavaScript**，
所以它們讀不到後台設定的圖，只讀得到 `index.html` 裡寫死的那一張。

請放一張 `og-cover.jpg` 到 `frontend/public/`，建議 1200×630，
橫式的蜂場實景照最好。放好之後分享連結才會有像樣的預覽。

> 想讓**每個商品**都有自己的分享預覽，需要 SSR 或預渲染 ——
> 那是換前端架構的等級，你之前選擇先不動，這件事還在待辦裡。

### ☐ 9. 備份

- 訂單與會員資料每日自動備份
- **實際演練還原一次**。沒測過的備份等於沒有備份

Zeabur 的資料庫服務有備份選項，開了之後找一天試著還原到另一個資料庫確認。

### ☐ 10. 監控

- 錯誤監控：Sentry（免費方案就夠這個規模）
- 服務存活監控：UptimeRobot 之類的，監控 `api.huanglong-honey.com/api/health`
  （這支刻意不碰資料庫，所以它有回應就代表程式活著）

### ☐ 11. 專業信箱

`service@huanglong-honey.com` 取代 gmail。你已經有網域和 Resend，
加一個收信服務就好，信任感差很多。

### ☐ 12. 檢驗報告

農藥殘留、抗生素、水分含量、HMF 的檢測報告掃描檔。

**這是純蜜最有力的說服工具，比任何文案都有效。**
拿到之後可以放在品牌故事或新增一則報導，我可以幫你做一個專門的頁面。
