# 未付款與付款失敗的處理

線上賣東西一定會遇到的三件事：信用卡被拒絕、ATM 忘記轉帳、超商代碼過期。
這份說明買家會看到什麼、你在後台要做什麼，以及系統自己會處理什麼。

---

## 一、核心原則：不要叫買家重新下單

買家付款失敗時，最糟的處理方式是叫他「重新下一次單」。原因：

- **折價券會卡住** —— 券在下單時就被標記為已使用
- **庫存會被扣兩次** —— 舊訂單還佔著，新訂單又扣一次
- **會員折扣可能不一樣** —— 如果中間升級了，金額對不上
- **買家很可能就放棄了**

所以整套流程都是「**同一筆訂單重新付款**」。訂單編號不變、金額不變、折扣不變。

---

## 二、買家看到什麼

### 訂單頁最上方的付款區塊

只要訂單還沒付款，訂單頁最上面就會出現一塊醒目的區域（排在訂單內容前面），
裡面有應付金額、剩餘時間、和兩個按鈕：

| 情況 | 標籤 | 主要按鈕 |
|---|---|---|
| 還沒去付款 | 尚未付款 | 立即前往付款 |
| ATM／超商代碼已取號 | 等待繳費 | 重新取號並前往付款 |
| 付款失敗 | 付款失敗（紅色）| 再付款一次 |
| 超過期限 | 已逾期（紅色）| 不給付款，請重新下單 |
| 訂單已取消 | 訂單已取消（灰色）| 重新選購 |

付款失敗時會**直接把綠界回傳的原因寫出來**（例如「銀行拒絕授權」），
並補上常見原因：額度不足、卡片沒開通網路交易、3D 驗證簡訊沒收到。

### 改用其他付款方式

第二個按鈕是「改用其他付款方式」，展開後可以在信用卡／ATM／超商代碼之間切換。
選了就直接帶去付款，少一次點擊。

- 金額和折扣完全不變
- 舊的虛擬帳號、繳費代碼會作廢（不然買家可能對著過期的號碼繳錢）
- 已經建立物流單的訂單不給改 —— 那代表你已經在出貨了

### 剩餘時間

顯示成「還有 2 天 5 小時」這種講法，剩不到一天會變紅色。
時間每分鐘自動更新，不會停在打開頁面的那一刻。

### 買家自己取消

登入的會員可以自己取消未付款的訂單，庫存立刻還原。
**訪客訂單不給自助取消** —— 訂單編號是時間戳，猜得到，
只憑編號就能取消的話，別人可以惡意刪掉你的訂單。訪客請走客服。

### 會員中心的置頂提醒

有未付款訂單時，會員中心最上方會出現紅色區塊列出來，每一筆旁邊都有「立即付款」。
埋在訂單表格裡的話，買家常常以為自己已經買到了。

## 三、你在後台要做什麼

**後台管理 → 訂單與出貨管理**，最上面有三個數字，點一下就是篩選：

| 數字 | 意思 |
|---|---|
| 待出貨 | 已付款（或貨到付款）但還沒建物流單 —— 今天要做的事 |
| 待付款 | 還沒收到錢，旁邊是金額總計 |
| 逾期未付款 | 超過期限，錢多半收不到了，但**庫存還被卡著** |

有逾期訂單時，上方會跳出提醒和「立即清理逾期訂單」按鈕。

### 展開單筆未付款訂單，有三個按鈕

**向綠界查詢付款狀態**
綠界的付款通知偶爾會漏掉（網路斷線、伺服器重啟）。
這個按鈕直接去問綠界「這筆到底付了沒」，是最常用的對帳工具。

**手動註記已收款**
用在綠界以外的收款：買家直接匯款到你的戶頭、面交付現。
註記後會照正常流程計入會員累積消費並發券，跟線上付款成功一模一樣。

**取消訂單並還原庫存**
買家說不買了、或是聯絡不上。庫存會自動加回去。

同時也會顯示：最近一次的失敗原因、買家嘗試付款幾次、付款期限。
**嘗試很多次還是失敗**通常代表卡片有問題，值得主動用 LINE 問一下。

## 四、系統自己會做的事

### 每小時清一次逾期訂單

後端每小時跑一次，把超過期限的未付款訂單自動取消並還原庫存。

只處理符合這四個條件的訂單，其他一律不碰：

1. 線上付款（貨到付款沒有付款期限）
2. 還在「待處理」狀態
3. 還沒付款
4. **還沒建立物流單** —— 已經在出貨了就不該自動取消，帳會對不起來

保留天數在 **網站設定 → 運費設定 → 未付款訂單保留天數**，預設 3 天。
填 0 表示永不自動取消（不建議，庫存會一直被卡住）。

> 3 天不是隨便訂的 —— 綠界的 ATM 虛擬帳號和超商代碼繳費期限本來就是 3 天。

### 庫存不會重複加

用旗標記住「這筆訂單的庫存已經還過了」。
不管自動清理跑幾次、你手動改幾次狀態，都只會加回去一次。

## 五、技術上最關鍵的一件事

**綠界的 `MerchantTradeNo` 不可重複。**

同一組編號送第二次會被退回「MerchantTradeNo is exist」。
所以重新付款不能直接把原本的訂單編號再送一次。做法：

| 第幾次付款 | 送給綠界的編號 |
|---|---|
| 第 1 次 | `20260817120000123`（訂單編號本身）|
| 第 2 次 | `20260817120000R2` |
| 第 3 次 | `20260817120000R3` |

綠界回呼時，系統會依序用「最後送出的編號 → 原始訂單編號 → 去掉 R 尾碼」找回訂單。
三層都試是為了處理這種情況：

> 買家第一次選 ATM 拿到虛擬帳號，後來改用信用卡付掉了，
> 但過幾天他忘記了又去轉帳給那個舊的虛擬帳號。
> 綠界會用**第一次**的編號通知我們 —— 系統還是要認得出這是哪一筆。

金額不符時系統會拒絕（回 `0|Amount Mismatch`）並寫進紀錄，不會自動改成已付款。
這種情況要人工看，不能讓程式自己決定。

## 六、新增的 API

| 方法 | 路徑 | 誰能用 | 說明 |
|---|---|---|---|
| GET | `/api/payments/{order_no}/checkout` | 任何人 | 前往付款（第二次以後就是重新付款）|
| POST | `/api/payments/{order_no}/mark-paid` | 工作人員 | 手動註記已收款 |
| PATCH | `/api/orders/by-no/{order_no}/payment-method` | 訂單本人 | 換一種付款方式 |
| POST | `/api/orders/by-no/{order_no}/cancel` | 訂單本人（需登入）| 買家自行取消 |
| POST | `/api/orders/expire-unpaid` | 工作人員 | 手動清理逾期訂單 |

`OrderOut` 新增的欄位：

| 欄位 | 說明 |
|---|---|
| `payment_deadline` | 繳費期限。**即時算出來的，不存資料庫** —— 你改保留天數，所有訂單一起跟著改 |
| `can_retry_payment` | 現在能不能重新付款 |
| `payment_message` | 最近一次的失敗原因 |
| `payment_attempts` | 嘗試付款次數 |
| `cancel_reason` | 取消原因 |

## 七、資料表變動

程式啟動時會自動補齊，**不需要重建資料庫**。`orders` 新增：

| 欄位 | 說明 |
|---|---|
| `payment_trade_no` | 最後一次送給綠界的交易編號 |
| `payment_attempts` | 付款嘗試次數 |
| `payment_message` | 最近一次失敗原因 |
| `cancel_reason` | 取消原因 |
| `stock_restored` | 庫存是否已還原（防重複）|
